**한줄 요약:**

RePAIR는 RAG의 오류를 세부적으로 분류하지 않고, 잘못된 답변에서 필요한 수정 행동(Action)을 직접 학습하는 방법으로, 2단계 DPO 학습을 통해 기존 RAG 대비 평균 F1 점수를 3.8%p 향상시킨다.

**짧은 요약(Abstract) :**

기존 Agentic RAG는 LLM 기반 Critic이 답변의 오류를 분석하고, 오류 유형에 따라 검색이나 답변 생성을 다시 수행한다. 하지만 Critic이 오류의 원인을 잘못 판단하면 불필요한 검색이나 잘못된 수정이 발생하여 오히려 성능이 떨어질 수 있다.

이 논문은 **정확한 오류 분류 없이도 RAG의 답변을 효과적으로 수정할 수 있다**는 가설에서 출발한다.

이를 위해 제안한 RePAIR는 잘못된 RAG 응답과 검색 문서를 입력받아, 어떤 수정 행동을 수행할지 직접 학습하는 Response–Action Learning 방법이다.

학습은 두 단계로 이루어진다.

1. **Off-policy training:** 정답과 오류 관련 정보를 활용해 효과적인 수정 계획을 학습한다.
2. **On-policy training:** 실제 추론 환경처럼 정답을 제공하지 않고, 모델이 생성한 수정 계획을 평가하며 정책을 개선한다.

세 가지 QA 벤치마크에서 기존 RAG 및 Critic 기반 Agentic RAG보다 높은 평균 성능을 보였으며, 불필요한 검색과 수정 행동도 줄였다.

Traditional agentic RAG systems rely on LLM-based critics to identify errors and recommend corrective actions. However, incorrect diagnoses can trigger unnecessary retrieval or ineffective refinements, sometimes degrading performance.

This paper introduces **RePAIR**, a response–action learning framework that directly maps flawed RAG responses to corrective action plans without explicit error taxonomies.

RePAIR uses two training phases:

1. **Off-policy training:** Learns corrective plans using ground-truth correctness signals and reasoning traces.
2. **On-policy training:** Refines the policy under inference-like conditions without access to ground-truth answers as inputs.

Experiments on three QA benchmarks demonstrate that RePAIR outperforms standard RAG and critic-guided baselines while reducing redundant actions.

# **단어정리**

- **Retrieval-Augmented Generation (RAG):** 검색 증강 생성. 외부 문서를 검색하고, 검색 결과를 근거로 LLM이 답변을 생성하는 방식.
- **Agentic RAG:** 검색과 생성뿐 아니라 답변 평가, 추가 검색, 수정 등의 행동을 계획하고 수행하는 RAG.
- **Critic Agent:** 생성된 답변을 평가하고 오류나 개선점을 판단하는 에이전트.
- **Error Taxonomy:** 오류 분류 체계. 검색 실패, 정보 부족, 추론 오류 등 오류를 사전에 정의된 유형으로 구분하는 방식.
- **Response–Action Learning:** 모델의 응답 상태를 보고 적절한 수정 행동을 직접 학습하는 접근법.
- **Action Plan:** 답변을 개선하기 위한 행동들의 순서. 예를 들어 Query Rewrite → Retrieval → Generate Answer.
- **Policy (**(pi_theta)**):** 현재 입력에 대해 어떤 행동 계획을 선택할지 결정하는 학습된 모델.
- **Executor:** Planner가 생성한 행동 계획을 실제로 실행해 수정된 답변을 만드는 구성 요소.
- **Off-policy Training:** 현재 정책이 생성한 행동이 아닌, 외부 Teacher가 생성한 행동 데이터 등을 이용해 학습하는 방식.
- **On-policy Training:** 현재 정책이 생성한 행동을 평가하고 이를 다시 학습에 사용하는 방식.
- **Direct Preference Optimization (DPO):** 더 좋은 출력과 더 나쁜 출력의 선호 관계를 이용해 모델을 학습시키는 방법.
- **Oracle Signal:** 정답을 알고 있는 상황에서 얻을 수 있는 정확성 판단 정보.
- **Train–Test Mismatch:** 학습 때 제공되는 정보와 실제 추론 때 제공되는 정보가 달라 발생하는 성능 저하 문제.
- **Token-level F1:** 생성 답변과 정답 사이의 토큰 단위 Precision과 Recall을 종합한 평가 지표.
- **Latent Error Categorization:** 오류 유형을 직접 출력하거나 지도하지 않고, 정책 내부에서 암묵적으로 반영하는 방식.

* **Retrieval-Augmented Generation (RAG):** A framework that retrieves external documents and uses them to ground LLM-generated responses.
* **Agentic RAG:** A RAG architecture that plans and executes additional operations such as retrieval, evaluation, and answer refinement.
* **Critic Agent:** An agent that evaluates generated answers and identifies potential errors or improvements.
* **Error Taxonomy:** A predefined classification of failure types, such as retrieval failures, incomplete evidence, or reasoning errors.
* **Response–Action Learning:** Learning a direct mapping from response states to corrective actions.
* **Action Plan:** An ordered sequence of operations intended to improve a generated answer.
* **Policy (**(pi_theta)**):** A learned model that selects action plans based on the current RAG state.
* **Executor:** A component that executes a generated plan to produce a revised answer.
* **Off-policy Training:** Learning from candidate actions produced by an external policy or teacher.
* **On-policy Training:** Learning from actions generated by the current policy.
* **Direct Preference Optimization (DPO):** A preference-learning method that optimizes a model using comparisons between preferred and rejected outputs.
* **Oracle Signal:** Correctness information obtained with access to ground-truth answers.
* **Train–Test Mismatch:** A discrepancy between training and inference conditions.
* **Token-level F1:** A metric measuring token overlap between predicted and reference answers.
* **Latent Error Categorization:** Implicit modeling of error information without explicitly predicting error categories.

# **Methodology**

## **1. Problem Definition**

기존 Critic 기반 Agentic RAG는 일반적으로 다음 과정을 따른다.

```
Question
   ↓
Retrieve Documents
   ↓
Generate Initial Answer
   ↓
Critic: Identify Error Type
   ↓
Planner: Select Corrective Actions
   ↓
Execute Actions
   ↓
Final Answer
```

문제는 Critic이 오류 유형을 잘못 판단하면 Planner 역시 잘못된 행동을 선택할 수 있다는 점이다.

예를 들어 이미 충분한 문서가 검색되었는데도 Critic이 이를 검색 실패로 판단하면, 불필요하게 검색을 반복하게 된다.

RePAIR는 이 중간 오류 분류 단계를 제거한다.

```
Question + Retrieved Documents
             ↓
       Initial Answer
             ↓
     RePAIR Planner
             ↓
     Corrective Action Plan
             ↓
          Executor
             ↓
       Refined Answer
```

핵심은 **오류 유형을 먼저 예측하는 대신, 현재 RAG 상태에서 최종 답변을 개선할 행동을 직접 선택**하는 것이다.

Conventional critic-based agentic RAG systems first classify errors and then generate corrective plans.

However, incorrect error classifications can lead to inappropriate actions, such as unnecessary retrieval when sufficient evidence is already available.

RePAIR removes explicit error categorization and directly learns a mapping from the current RAG state to corrective action plans.

Instead of optimizing diagnostic accuracy, RePAIR focuses on learning actions that improve final answer quality.

## **2. RAG State and Action Space**

RePAIR의 입력 상태는 다음 정보로 구성된다.

- (q): 사용자 질문
- (D): 검색된 문서 집합
- (a_0): 초기 RAG 답변
- (a_{text{gold}}): 정답 (학습 및 평가 시 사용)

훈련 단계에 따라 Planner에 제공되는 정보가 달라진다.

**Off-policy 입력:**

[ x_{text{off}}=(q,D,a_0,c,r_0) ]

- (c): 정답과 비교해 얻은 초기 답변의 정오 여부
- (r_0): 초기 답변의 잘못된 reasoning trace

**On-policy 및 Inference 입력:**

[ x_{text{on}}=(q,D,a_0,hat{c}) ]

- (hat{c}): 정답 없이 LLM Judge가 추정한 대략적인 정오 여부

여기서 중요한 점은 Inference에서도 완전히 평가 신호가 없는 것은 아니라는 것이다. **세부 오류 유형은 제거하지만, 답변이 맞았는지에 대한 이진 추정 신호는 사용한다.**

Planner는 다음 다섯 가지 연산으로 행동 계획을 구성한다.

| Action          | 역할                 |
| --------------- | ------------------ |
| REWRITE         | 검색 질문을 수정          |
| DECOMPOSE       | 복잡한 질문을 하위 질문으로 분해 |
| RETRIEVAL       | 추가 문서 검색           |
| REFINE DOC      | 검색 문서의 내용을 정제      |
| GENERATE ANSWER | 주어진 문서를 바탕으로 답변 생성 |

행동 계획은 다음과 같이 나타낸다.

[ y=(o_1,o_2,ldots,o_T),quad o_tinmathcal O ]

즉, 하나의 답변을 고치기 위해 필요한 연산의 순서를 모델이 생성한다.

RePAIR represents the current RAG state using the question, retrieved documents, and initial response.

During off-policy training, additional oracle correctness labels and incorrect reasoning traces are available:

[ x_{text{off}}=(q,D,a_0,c,r_0) ]

During on-policy training and inference, the planner only receives:

[ x_{text{on}}=(q,D,a_0,hat{c}) ]

Here, (hat{c}) is a coarse correctness estimate generated without access to the gold answer.

The planner selects a variable-length sequence of actions from five predefined operations: REWRITE, DECOMPOSE, RETRIEVAL, REFINE DOC, and GENERATE ANSWER.

Thus, RePAIR removes fine-grained diagnostic labels while retaining a structured corrective action space.

## **3. Response–Action Policy Learning**

RePAIR는 단순히 좋은 수정 계획을 생성하도록 Supervised Fine-Tuning하는 방식이 아니다.

여러 수정 계획을 실제 실행해 본 뒤, **어떤 계획이 더 좋은 최종 답변을 만들었는지 비교하여 학습**한다.

먼저 Planner가 여러 후보 행동 계획을 생성한다.

[ Y={y_1,y_2,ldots,y_n} ]

각 계획을 Executor로 실행한다.

[ hat a(y;x)=operatorname{Executor}(x,y) ]

그다음 수정된 답변과 정답의 Token-level F1을 보상으로 계산한다.

[ R(x,y)=F1(hat a(y;x),a_{text{gold}}) ]

두 계획의 보상이 다르면 다음과 같은 선호 관계를 구성한다.

[ y_isucc y_j quad text{if}quad R(x,y_i)>R(x,y_j) ]

이를 통해 ((x,y^+,y^-)) 형태의 Preference Pair를 만들고 DPO로 학습한다.

[ mathcal L_{mathrm{DPO}} = -log sigmaleft( betalog frac{ pi_theta(y^+mid x)/pi_{mathrm{ref}}(y^+mid x) }{ pi_theta(y^-mid x)/pi_{mathrm{ref}}(y^-mid x) } right) ]

여기서

- (pi_theta): 학습 중인 Planner
- (pi_{mathrm{ref}}): 기준 정책
- (y^+): 더 좋은 F1을 얻은 계획
- (y^-): 상대적으로 낮은 F1을 얻은 계획
- (beta): 기준 정책으로부터의 변화 정도를 조절하는 계수

중요한 점은 **개별 행동의 정답을 직접 지정하지 않고, 행동 계획 전체를 실행한 결과를 비교한다**는 것이다.

RePAIR formulates corrective planning as preference-based policy learning.

For each RAG state, the planner generates multiple candidate action plans. Each plan is executed to produce a revised answer, which is evaluated using token-level F1 against the ground-truth answer.

Plans are ranked by their resulting rewards, and preference pairs are constructed from better and worse candidates.

DPO then trains the planner to assign higher probabilities to plans that produce better answers.

This approach optimizes the effectiveness of complete action sequences rather than requiring explicit error labels or step-level action supervision.

## **4. Two-Phase Training**

RePAIR의 핵심 학습 전략은 Off-policy와 On-policy를 순차적으로 적용하는 것이다.

**Phase 1: Off-policy Bootstrapping**

초기 단계에서는 정답을 알고 있으므로 비교적 풍부한 정보를 활용할 수 있다.

1. 질문, 검색 문서, 초기 답변, 정오 레이블, 잘못된 reasoning trace를 입력한다.
2. Teacher Model이 여러 수정 계획을 제안한다.
3. 각각을 Executor로 실행한다.
4. 최종 답변의 F1을 측정한다.
5. 좋은 계획과 나쁜 계획을 비교하여 DPO로 학습한다.

이 단계의 목적은 학습 초기에 **효과적인 수정 행동의 패턴을 안정적으로 습득**하는 것이다.

다만 실제 추론에서는 정답이나 Oracle Reasoning Trace를 사용할 수 없다는 문제가 있다.

**Phase 2: On-policy Refinement**

두 번째 단계에서는 실제 추론 환경과 동일한 입력 형태로 학습한다.

1. 정답 여부의 추정값 (hat c)만 제공한다.
2. 현재 Planner가 직접 후보 계획을 생성한다.
3. 계획을 실행하고, 학습 시 보유한 정답으로 F1을 계산한다.
4. 새로운 Preference Pair를 구성한다.
5. DPO로 Planner를 추가 최적화한다.

이를 통해 첫 단계의 Oracle 의존성을 줄이고, 실제 추론 환경에 적합한 정책을 학습한다.

참고로 On-policy 학습에서도 **보상을 계산할 때는 정답을 사용한다.** 정답이 제거되는 것은 Planner의 입력이며, 실제 Inference에서는 보상 계산이나 DPO 업데이트를 수행하지 않는다.

**Phase 1: Off-policy Bootstrapping**

The first phase uses oracle correctness labels and incorrect reasoning traces to provide stronger training signals.

A teacher model proposes candidate corrective plans, which are executed and evaluated against ground-truth answers. Preference pairs are constructed from the resulting rewards and used for DPO training.

This stage provides stable initialization but introduces a mismatch between training and deployment conditions.

**Phase 2: On-policy Refinement**

The second phase removes oracle information from the planner's inputs.

The current policy generates candidate plans using deployment-style states. These plans are executed and scored against ground-truth answers during training, and new preference pairs are used for further DPO optimization.

Combining both stages provides stable initial learning and better alignment with inference conditions.

# **Results**

## **1. Experimental Setup**

세 가지 QA 데이터셋에서 평가했다.

RePAIR is evaluated on three QA benchmarks: Natural Questions, Wizard of Wikipedia, and 2WikiMultiHopQA.

These datasets cover single-hop factual QA, knowledge-grounded dialogue, and multi-hop reasoning.

The evaluation compares RePAIR against standard RAG and five agentic RAG baselines, using shared backbone configurations and token-level F1 as the primary metric.

| Two-phase RePAIR  | **30.0**   |

Off-policy만 사용하는 경우 Oracle 정보에 의존해 학습하기 때문에 실제 추론 환경과 차이가 발생한다.

반대로 On-policy만 사용하는 경우 실제 환경과 입력 형태는 같지만, 학습 초기에 충분한 지도 신호가 없어 효과적인 수정 정책을 배우기 어렵다.

두 단계를 결합하면 초기 학습 안정성과 실제 환경 적응을 모두 확보할 수 있다.

The ablation study demonstrates that combining both training phases produces better performance than either phase alone.

Off-policy-only training suffers from the mismatch between oracle-rich training inputs and inference inputs.

On-policy-only training avoids this mismatch but lacks sufficiently strong initial supervision.

The full two-phase approach addresses both limitations, achieving an average F1 of 30.0.

## **4. Action Efficiency**

논문은 세부 오류 분류 없이 학습한 이후 Planner가 수행하는 행동 수가 어떻게 변하는지도 분석한다.

Table 3, 논문 p.4 (인쇄 페이지 158). 숫자는 분석된 행동의 사용 횟수이며, 최종 답변 생성은 제외된다.

| Dataset | Action    | Before | After | Change |
| ------- | --------- | ------ | ----- | ------ |
| NQ      | Retrieval | 310    | 138   | -55.5% |
| NQ      | Rewrite   | 12     | 0     | -100%  |
| 2Wiki   | Retrieval | 1,563  | 491   | -68.6% |
| 2Wiki   | Rewrite   | 86     | 43    | -50.0% |
| 2Wiki   | Decompose | 14     | 11    | -21.4% |
| 2Wiki   | RefineDoc | 20     | 7     | -65.0% |
| WoW     | Retrieval | 8      | 7     | -12.5% |

특히 2Wiki에서 Retrieval 수행 횟수가 1,563회에서 491회로 크게 감소했다.

이는 RePAIR가 불필요한 추가 검색이나 질문 재작성을 줄이면서도 높은 정답 성능을 유지한다는 점을 보여준다.

다만 이 결과는 **행동 횟수 감소**를 보여주는 것으로, 실제 추론 지연 시간이나 전체 연산 비용 감소율을 직접 측정한 결과는 아니다.

RePAIR substantially reduces the number of auxiliary corrective actions after optimization.

For example, retrieval operations decrease by 55.5% on NQ and 68.6% on 2Wiki.

Query rewriting, decomposition, and document refinement also become less frequent.

These findings indicate that RePAIR learns more selective corrective behavior, avoiding redundant operations without sacrificing answer quality.

However, action-count reductions should not be interpreted as directly measured latency or computational cost savings.

# **예제**

논문의 Figure 1은 오류 분류가 잘못되었을 때 어떤 문제가 발생하는지 실제 사례로 설명한다.

**Question:**

> Which act governs the working of banking companies in India?

인도의 은행 회사 운영을 규율하는 법률은 무엇인가?

**Retrieved Documents:**

검색된 문서에는 다음 법률이 포함되어 있다.

- Banking Regulation Act, 1949
- Companies Act, 2013
- Reserve Bank of India Act, 1934

초기 RAG는 관련 문서를 검색했지만, 질문에서 요구한 법률을 명확하게 답하지 못했다.

**Case 1: 올바른 오류 판단**

문제가 검색 단계가 아니라 답변 생성 단계에 있다는 것을 정확하게 판단한다.

```
Initial Answer
      ↓
Answer-level Error
      ↓
GENERATE ANSWER
      ↓
Corrected Answer
```

이미 충분한 정보가 있으므로 답변만 다시 생성하면 된다.

**Case 2: 잘못된 오류 판단**

Critic이 이를 검색 정보 부족이나 관련 없는 문서 검색 문제로 잘못 분류한다.

```
Initial Answer
      ↓
Incorrect Error Classification
      ↓
REWRITE QUERY
      ↓
RETRIEVAL
      ↓
GENERATE ANSWER
```

정작 문제는 답변 생성에 있는데도 불필요한 검색 과정이 추가된다.

**Case 3: RePAIR**

RePAIR는 세부 오류 유형을 예측하지 않고 직접 수정 계획을 선택한다.

```
Initial Answer
      ↓
RePAIR Planner
      ↓
GENERATE ANSWER
      ↓
Corrected Answer
```

핵심은 원인을 세부적으로 설명하는 과정 없이도 적절한 수정 행동을 선택할 수 있다는 것이다.

Figure 1 illustrates a factual QA example about banking regulation in India.

The retrieved passages already contain relevant legal information, but the initial answer fails to identify the governing act directly.

With correct error categorization, the system selects GENERATE ANSWER to correct the response.

With incorrect categorization, the critic attributes the problem to retrieval, triggering unnecessary query rewriting and additional document retrieval.

RePAIR directly selects GENERATE ANSWER without fine-grained error classification.

This example demonstrates that learning corrective actions directly can avoid errors introduced by unreliable intermediate diagnoses.

# **요약**

이 논문은 **RAG 성능 개선을 위해 오류 유형을 반드시 세밀하게 분류할 필요는 없다**는 점을 실험적으로 보여준다.

기존 Agentic RAG가 Critic의 진단 결과를 기반으로 수정 행동을 선택했다면, RePAIR는 RAG의 현재 상태에서 효과적인 행동 계획을 직접 학습한다.

핵심적인 기여는 세 가지다.

1. **Response–Action Learning:** 오류 분류와 수정 계획 생성을 하나의 정책 학습 문제로 통합했다.
2. **Two-Phase DPO Training:** Oracle 기반 Off-policy 학습과 실제 추론 환경에 맞춘 On-policy 학습을 결합했다.
3. **Accuracy and Action Efficiency:** 세 가지 QA 벤치마크에서 평균 F1을 개선하면서 불필요한 수정 행동을 줄였다.

다만 실험은 세 가지 QA 데이터셋과 제한된 행동 공간에서 수행되었으며, 더 복잡한 Agentic Workflow나 노이즈가 심한 검색 환경에서의 일반화는 추가 검증이 필요하다.

**결국 RePAIR의 핵심은 오류를 얼마나 자세히 설명하는지가 아니라, 어떤 수정 행동이 실제로 답변을 개선하는지를 학습하는 데 있다.**

This paper demonstrates that explicit fine-grained error categorization is not necessary for effective RAG refinement.

RePAIR directly learns corrective action policies from RAG states rather than relying on critic-generated error taxonomies.

Its main contributions are response–action policy learning, two-phase DPO optimization, and empirical improvements in both answer accuracy and action efficiency.

The results suggest that optimizing corrective behavior can be more reliable than depending on potentially inaccurate diagnostic labels.

However, generalization beyond the evaluated QA benchmarks and predefined action space remains an open question.

The central takeaway is that **effective RAG refinement depends on selecting useful corrective actions, not necessarily on explicitly identifying every error type.**

# **기타(다이어그램, Figures, Tables, Appendix, 인사이트)**

## **1. Overall Architecture**

논문의 Methodology를 정리하면 다음과 같다.

```
             Initial RAG
                 |
       Question + Documents
                 |
           Initial Answer
                 |
        +--------+--------+
        |                 |
  Off-policy Phase   On-policy Phase
        |                 |
  Oracle Labels      Coarse Judge
  Reasoning Trace    Correctness Signal
        |                 |
  Teacher Plans      Current Policy Plans
        |                 |
   Execute Plans      Execute Plans
        |                 |
   Evaluate F1        Evaluate F1
        |                 |
  Preference Pairs   Preference Pairs
        |                 |
       DPO  ---------->  DPO
                          |
                    Trained Planner
                          |
                   Corrective Actions
                          |
                      Executor
                          |
                    Refined Answer
```

이 구조에서 Off-policy는 효과적인 수정 방법을 배우는 초기 단계이고, On-policy는 실제 사용 환경에서도 그 방법을 잘 선택하도록 조정하는 단계다.

The overall architecture consists of an initial RAG pipeline, a response–action planner, a deterministic executor, and a two-phase preference-learning procedure.

Off-policy learning provides stable initialization from teacher-generated plans and oracle signals.

On-policy learning further refines the policy using its own candidate plans under inference-matched inputs.

The resulting planner selects corrective operations without explicit fine-grained error taxonomies.

## **4. Additional Insights**

**Insight 1. Error Diagnosis와 Action Selection은 서로 다른 목표다.**

오류 유형을 정확하게 설명하는 모델이 반드시 최적의 수정 행동을 선택하는 것은 아니다.

RePAIR는 오류 분류의 정확도를 목표로 하지 않고, 최종 결과를 개선하는 행동을 학습 대상으로 삼는다.

**Insight 2. Fine-grained Critic은 필수적이지 않지만, Coarse Feedback은 여전히 유용하다.**

RePAIR는 세밀한 오류 분류를 제거했지만, On-policy와 Inference에서 LLM Judge가 추정한 정오 신호를 사용한다.

따라서 이 연구를 Critic을 완전히 제거한 방법으로 해석하기보다는, **세부 진단에 대한 의존도를 줄인 방법**으로 이해하는 것이 정확하다.

**Insight 3. 불필요한 행동을 줄이는 것도 Agentic RAG의 중요한 최적화 목표다.**

검색을 여러 번 수행한다고 반드시 답변이 좋아지는 것은 아니다.

RePAIR는 추가 행동을 무조건 늘리는 대신, 필요한 상황에서 선택적으로 수행하도록 학습한다.

**Insight 4. DPO는 정답 문장뿐 아니라 Agent의 행동 계획에도 적용할 수 있다.**

일반적인 Preference Learning은 답변의 품질을 비교하지만, 이 논문은 서로 다른 행동 계획을 실행한 결과를 비교한다.

이는 Agentic System에서 행동 선택 정책을 학습하는 하나의 방법으로 볼 수 있다.

**Insight 5. 논문의 한계와 추가 검증 지점**

- 실험은 세 가지 QA 벤치마크에 제한된다.
- Action Space가 다섯 가지 고수준 RAG 연산으로 제한된다.
- 각 행동의 실행 비용과 실제 Latency를 충분히 분석하지 않았다.
- 더 심한 검색 노이즈나 적대적인 문서 환경에서의 안정성은 검증되지 않았다.
- DPO에서 두 후보 모두 낮은 보상을 받는 경우에도 상대적 선호 관계를 만들 수 있어 학습 노이즈가 발생할 수 있다.

특히 Appendix E의 Prompt에는 여전히 `error_type`이라는 필드가 등장한다. 본문에서 정의한 On-policy 입력은 세부 오류 레이블을 제외하므로, 실제 구현에서 이 필드에 어떤 형태의 오류 신호가 제공되는지 확인할 필요가 있다.

**Insight 1. Error diagnosis and action selection are different objectives.**

A model that accurately describes an error does not necessarily select the most effective correction. RePAIR instead optimizes actions based on their impact on answer quality.

**Insight 2. Fine-grained criticism is unnecessary, but coarse feedback remains useful.**

RePAIR removes explicit error taxonomies while retaining a binary correctness estimate. It therefore reduces reliance on detailed critics rather than eliminating evaluation signals entirely.

**Insight 3. Selective actions matter more than frequent interventions.**

Additional retrieval or rewriting does not always improve answer quality. Learning when to avoid unnecessary actions is an important part of effective agentic RAG.

**Insight 4. Preference optimization can be applied to agent plans.**

RePAIR uses DPO to learn preferences over action sequences based on execution outcomes, extending preference learning beyond direct answer generation.

**Insight 5. Limitations and open questions.**

The framework is evaluated on a restricted set of QA tasks and predefined operations. Its robustness under adversarial retrieval, performance with more complex tool environments, and actual computational efficiency require further study.

Additionally, the prompt templates retain an `error_type` field even though the methodology removes fine-grained error labels from on-policy inputs. Clarifying this implementation detail would improve reproducibility.
